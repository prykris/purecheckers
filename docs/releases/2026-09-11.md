## Migration review

The previously tracked PostgreSQL baseline is `20260910000000_postgresql_init`; the candidate adds 24 migrations through `20260911140000_game_invitation_entry`. The main additions are puzzle records, durable command/settlement/game/room/result records, membership constraints and profile revisions.

Two data transformations need explicit awareness: puzzle-attempt deduplication merges strongest recorded progress before removing duplicate visitor attempts; guest retirement marks only the old exact expired-guest tombstone pattern. Gameplay recovery deliberately leaves old checkpoint/recovery markers ambiguous rather than guessing. Inspect unfinished legacy runs before replacement; do not erase them to force startup.

The upgrade rehearsal uses representative baseline records. It is not a copy of production and cannot establish production's current migration history, schema drift or open-game state.
